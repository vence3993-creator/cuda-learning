# CUDA 共享内存 bank 冲突笔记

> 来源：《CUDA 编程：基础与实践》（樊哲勇）第 9 章 · 矩阵转置核函数

---

## 一、背景代码

```cpp
__global__ void transpose1(const real *A, real *B, const int N)
{
    __shared__ real S[TILE_DIM][TILE_DIM];      // TILE_DIM = 32
    int bx = blockIdx.x * TILE_DIM;
    int by = blockIdx.y * TILE_DIM;

    int nx1 = bx + threadIdx.x;
    int ny1 = by + threadIdx.y;
    if (nx1 < N && ny1 < N)
    {
        S[threadIdx.y][threadIdx.x] = A[ny1 * N + nx1];   // 写 S：同一行，无冲突
    }
    __syncthreads();

    int nx2 = bx + threadIdx.y;
    int ny2 = by + threadIdx.x;
    if (nx2 < N && ny2 < N)
    {
        B[nx2 * N + ny2] = S[threadIdx.x][threadIdx.y];   // 第 19 行：读 S 的一列，有冲突！
    }
}
```

改进写法：

```cpp
__shared__ real S[TILE_DIM][TILE_DIM + 1];   // 多加一列填充
```

## 二、基础概念

### 1. bank 的排列方式

- 共享内存物理上分为 **32 个 bank**，每个 bank 宽 **4 字节**（一个 `float`）。
- 数据按地址**依次轮流**放入各 bank，可以想象成一个 **32 列宽的表格**：每列是一个 bank，每行是一"层"。

```
bank 号 = 元素序号 % 32
层号    = 元素序号 / 32
```

### 2. 什么是 bank 冲突

同一个**线程束**中的多个线程，访问了**同一个 bank 的不同层**。

一个 bank 一次只能取出一层数据，这些访问只能排队串行执行。N 个线程撞在同一个 bank 上，就叫 N 路 bank 冲突，速度降为原来的 1/N。

> 注意：多个线程访问**同一个地址**不算冲突（会广播）。

### 3. 二维数组的内存布局

`S[r][c]` 在内存中按行展开，序号为：

```
序号 = r × 每行长度 + c
```

### 4. 线程束的划分

线程按线性编号 `threadIdx.x + threadIdx.y * blockDim.x` 每 32 个一组划分线程束。

本例中 `blockDim.x = 32`，所以：**同一线程束内 `threadIdx.y` 相同，`threadIdx.x` 从 0 到 31 连续变化。**

---

## 三、原来的写法为什么有冲突：`S[32][32]`

每行长度 32，`S[r][c]` 的 bank 号为：

```
(r × 32 + c) % 32 = c
```

**bank 号只由列号决定，同一列的元素全在同一个 bank 里。** 数组的行恰好就是 bank 的层：

```
          bank0    bank1    bank2   ...  bank31
第0层    S[0][0]  S[0][1]  S[0][2]  ...  S[0][31]
第1层    S[1][0]  S[1][1]  S[1][2]  ...  S[1][31]
第2层    S[2][0]  S[2][1]  S[2][2]  ...  S[2][31]
 ...
```

第 19 行读 `S[threadIdx.x][threadIdx.y]`，对第 k 个线程束：

- `threadIdx.y = k` 固定，`threadIdx.x = 0 ~ 31`
- 访问 `S[0][k], S[1][k], ..., S[31][k]` —— **同一列**
- 全部落在 **bank k**，只是层数不同

➡️ **32 路 bank 冲突**，最坏情况，完全串行。

---

## 四、加一列填充为什么能消除冲突：`S[32][33]`

每行长度 33，`S[r][c]` 的 bank 号为：

```
(r × 33 + c) % 32 = (r × 32 + r + c) % 32 = (r + c) % 32
```

**bank 号由"行号 + 列号"决定。** 每行比一层多一个元素，所以每往下一行，整行向右错开一个 bank：

```
          bank0     bank1     bank2     bank3   ...
第0层    S[0][0]   S[0][1]   S[0][2]   S[0][3]  ...
第1层    S[0][32]  S[1][0]   S[1][1]   S[1][2]  ...   ← S[1][0] 移到 bank1
第2层    S[1][31]  S[1][32]  S[2][0]   S[2][1]  ...   ← S[2][0] 移到 bank2
第3层    ...       ...       ...       S[3][0]  ...   ← S[3][0] 移到 bank3
```

（`S[r][32]` 是填充的占位元素，不存有效数据，作用是把下一行往后推一格。）

同一列 `S[0][k], S[1][k], ..., S[31][k]` 所在的 bank：

```
k, k+1, k+2, ..., k+31    （对 32 取余）
```

➡️ 正好是 **32 个互不相同的 bank**，一次取完，**冲突完全消除**。

原本竖着排在同一个 bank 里的一列数据，变成了斜着排开的一条**对角线**。

## 五、常见疑问

### Q1：为什么是 `+1`，不是 `+2`？

关键在于每行长度与 32 **互质**。

- 每行 33：沿一列往下走，bank 号每次 +1，32 步正好经过全部 32 个 bank ✅
- 每行 34：bank 号每次 +2，只能走到偶数号 bank，32 个线程挤在 16 个 bank，仍有 **2 路冲突** ❌

`+1` 是最省空间又能完全消除冲突的做法。

### Q2：bank 物理上只有 32 个，多一列不就变成 33 个了吗？

**不会，bank 始终是 32 个。** 变的只是数组的逻辑形状。

- 物理上，共享内存就是一段连续存储，按 4 字节一格排成一长串，再按 `地址 % 32` 分到 32 个 bank。
- 二维数组 `S[32][33]` 在内存里被展开成 1056 个元素的一长串，"每行 33 个"只是编译器计算地址的规则（`r × 33 + c`）。
- 硬件不知道数组有几行几列，只看地址。
- 原来"数组一行 = bank 一层"只是因为行长恰好也是 32，**碰巧对齐**。改成 33 后，数组一行比一层长一格，会溢出到下一层，行和层不再对齐——**这种错位正是消除冲突的原因**。

> 📝 比喻：方格纸每行固定 32 格（32 个 bank），每句话写 33 个字。纸不会变成 33 格宽，只是每句话最后一个字折到下一行，于是每句开头都比上一句往右错一格。

### Q3：加填充有什么代价？

多出的一列不存有效数据，浪费 32 个元素：

- `float`：128 字节
- `double`：256 字节

相对于每个线程块 48 KB 的共享内存上限可以忽略，换来最多 32 倍的访问速度提升，非常划算。

### Q4：会不会让写入 S 的那一步产生新的冲突？

不会。写入 `S[threadIdx.y][threadIdx.x]` 时，同一线程束访问的是**同一行**连续 32 个元素，bank 号为 `(k + 0), (k + 1), ..., (k + 31)`，依然互不相同，无冲突。

## 六、相关知识点补充

### `__shared__` 变量是每个线程块一份

- 普通局部变量（`tid`、`nx1` 等）存在**寄存器**，每个线程私有一份。
- `__shared__` 变量存在**共享内存**，**同一线程块内所有线程共用一份**。
- 本例一个块 32×32 = 1024 个线程，共用一个 32×32 的 `S`，每个线程负责其中一个元素。

### 共享内存在转置中的作用

目的是让**读 A 和写 B 都实现合并访问**：

1. 读 A：`threadIdx.x` 对应列，线程束读 A 的一行连续元素 → 合并 ✅
2. 转置在**共享内存**里完成（`S[threadIdx.x][threadIdx.y]`），片上跳跃访问代价小
3. 写 B：`threadIdx.x` 对应列，线程束写 B 的一行连续元素 → 合并 ✅

唯一遗留问题就是第 2 步读 S 的一列会产生 bank 冲突，用 `+1` 填充解决。

### CUDA 中 x 管列，y 管行

- 沿用平面坐标习惯：x 横轴 → 列，y 纵轴 → 行。
- 本质原因：线程束内 `threadIdx.x` 连续变化，矩阵按行存储时同一行的相邻列在内存中连续，所以让 `threadIdx.x` 对应列才能合并访问。

---

## 七、一句话总结

> **原数组每行 32 个元素，同一列全在一个 bank，读一列产生 32 路冲突；每行加一个填充元素变成 33 个，每行向右错开一个 bank，同一列分散到 32 个不同 bank，冲突消除。bank 数量不变，变的只是数据在 bank 中的排布。**
